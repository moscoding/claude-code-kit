# Задачи для launch-kit

Три задачи для GitHub Issues. Заголовок задачи — строка после `## `,
описание — текст до следующего `## `. Создавайте задачи в этом порядке.

## Показать дату обновления на странице статуса

Руководитель открывает страницу статуса утром и не видит, на какую дату
собраны данные.

Что сделать: `scripts/build_status.py` читает дату из
`inputs/status-date.txt` (одна строка `ГГГГ-ММ-ДД`) и выводит на странице
строку «Обновлено: ДД.ММ.ГГГГ». По этой же дате скрипт считает просрочки
вместо даты, записанной в коде.

Критерии приёмки:
- приёмочный тест `tests/test_status_date.py` из набора проходит, файл теста не изменён;
- `outputs/status.html` пересобран скриптом и закоммичен, руками страницу не правят;
- с датой `2026-05-15` блоки страницы остались прежними, добавилась только строка с датой.

Вне скоупа: время и часовой пояс, дата с часов компьютера, новый дизайн страницы.

## Показать число задач в заголовке блока «Блокеры и просрочки»

На созвоне сначала спрашивают, сколько задач под угрозой.

Что сделать: заголовок блока выглядит как «Блокеры и просрочки (2)», где
число — количество задач в блоке.

Критерии приёмки:
- на учебных данных на 15 мая в заголовке стоит 2;
- число считает скрипт по данным, а не берёт из текста;
- тест на это число добавлен в `tests/`.

Вне скоупа: счётчики в других блоках.

## Описать в README, как пересобрать страницу и проверить её

Новый человек в команде не знает, какими командами обновить страницу.

Что сделать: в `README.md` раздел «Как обновить страницу» с двумя командами
и одной фразой о каждой: `python3 scripts/build_status.py` и
`python3 -m unittest -v`.

Критерии приёмки:
- обе команды выполняются из корня репозитория без ошибок;
- в README сказано, что `outputs/status.html` руками не правят.

Вне скоупа: инструкция по установке Python и Git.
